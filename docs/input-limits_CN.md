# 输入大小与读取中变化的文件

[English](input-limits.md) · [项目检查](project_CN.md) · [修改审阅](review_CN.md)

项目检查、评审证据保留与离线验证使用有上限的普通文件读取。输入过大或读取中
发生可观察变化时，命令报错，不发布不完整的检查或评审目录。已有目标目录继续受保护。

| 输入 | 上限 | 检查时机 |
|---|---:|---|
| 单个源码或 `.als.json` | 2,000,000 字节 | 清点与实际源码读取 |
| 评审备注（`--notes`） | 2,000,000 字节 | 创建评审暂存目录之前 |
| 共用辅助函数读取、写入的 JSON 元数据 | 16 MiB | 解析或写入之前 |
| 单个被计算指纹、复制的资源或证据文件 | 512 MiB | 打开之前与读取过程中 |
| 评审每侧项目清单 | 2 GiB、5,000 个文件 | 计算指纹前；再次核对实际读取字节总量 |
| 单个密封交付物清单 | 2 GiB、20,000 个文件 | 密封前与验证过程中 |

MiB、GiB 按 1024 计算，恰好等于上限可以接受。源码和备注按 UTF-8 字节计数，
包含 BOM，不按字符数计数。这些是工具的处理边界；项目文件的选择与排除目录规则
见[项目检查](project_CN.md)和[修改审阅](review_CN.md)。交付物总量在密封时检查，
并不限制所有构建中间文件占用的磁盘空间。

以下命令中的备注与构建报告会在发布评审目录前检查：

```sh
als --json review --before original --after candidate --output ../review \
  --notes review-notes.txt --after-build candidate-build/build-report.json
```

评审输入错误返回退出码 `2`；使用 `--json` 时，错误保留在 `result.error` 字段中。
可以精简备注、移出无关的被清点文件，或改用较小且相关的资源与证据，然后使用新
输出目录重试。未提供可选构建报告时，构建状态仍为 `unverified`。

每次读取前后都检查普通文件类型、描述符与路径的身份、大小和修改信息；共用辅助
函数拒绝符号链接与特殊文件。在 POSIX 上，非阻塞、禁止跟随链接的打开标志也防止
首次检查后被替换的 FIFO 阻塞读取。复制字节数与摘要来自同一次读取；构建报告
摘要绑定实际被解析的字节。发布前还会重新检查原始输入与保留证据。

检查覆盖观察到的变化，不会锁定项目；不能证明证据来源、发现所有在两次观察间
完全恢复的修改，或证明科学内容正确。远程文件系统可用性仍可能影响 I/O 等待时间。
保留不变的原稿，在另一个候选目录中修改。

[回归测试](../tests/test_bounded_io.py)覆盖临界大小、实际流增长、文件替换、同大小
修改、提前拒绝、备注编码与转义、解析字节绑定和失败清理。跨平台 CI 检查 POSIX
与 Windows 行为；wheel 和从 sdist 重建的安装包在仓库外验证公开上限。这些属于
合成工具检查。
