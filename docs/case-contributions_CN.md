# 贡献可复现的论文案例

[English](case-contributions.md) · [贡献流程](../CONTRIBUTING.md)

现有案例均为合成输入。欢迎具有可再分发许可、来源记录和可复现证据的真实案例。
没有这些证据时，不应标注为真实用户案例。匿名化本身不能证明具有再分发许可。

## 案例目录

新建 `examples/CASE_ID/`，包含：

| 文件 | 必需内容 |
|---|---|
| `README.md` | 问题、来源、范围、可执行命令、依赖、预期结果和局限 |
| `PROVENANCE.md` | 合成/真实分类、原始来源、再分发许可/许可证、署名和脱敏说明 |
| `before/` | 能复现问题的最小原始源码树，保留原始失败 |
| `after/` | 可审查的候选源码树，不暗中修改原稿 |
| `decisions.md` | 实质修改、保留的数量/主张、未决问题，以及实际取得的作者确认 |

保留第三方声明和许可证。生成的 PDF、日志、报告放在外部新目录，使用可下载的
CI 证据，不提交依赖本机环境的构建目录。恢复源码必需的输入 PDF 可以保留，
前提是记录其来源和再分发许可。

## 验收清单

- 移除凭据、个人标识及保密的审稿/作者材料；检查 TeX、注释、文献库、文件名和
  PDF 元数据。
- 提供必需的本地源码、样式和图件。单独说明用户需提供的官方模板或外部依赖，
  测试不能静默联网下载文件。
- 记录主文件、实际引擎/后端、相关包/字体要求及生成证据时的工具版本。多个根
  文件必须显式选择。
- 复现原始失败、候选结果和受保护字面量。有意保留的未解决引用应明确说明。
- 保留实际日志、源码差异、可用 PDF/页面对照与源码指纹。区分工具缺失、构建
  失败和内容不确定性，不为失败原稿制造 PDF。
- 检查应对应有意义的失败：缺失资源、模板冲突、原意变化、丢失单元格、伪造引用
  或漏页。简单字符串保留不能证明语义质量。
- 说明候选来自维护者编辑还是可追溯模型运行。后者只有带配对控制和人工审查，
  才能按[评测协议](evaluation_CN.md)进入效果比较。

## 优先覆盖

优先多文件、本地样式/文档类、中英内容、BibTeX/Biber、多个根文件与模板迁移。
新增案例应具有与现有案例明显不同的失败及验收标准。PDF 恢复案例覆盖公式、
表格空白/精度，以及矢量图或扫描内容的不确定性。

按[任务指南](tasks_CN.md)和[项目审查](review_CN.md)准备证据。验收后接入运行器
和 CI，避免只添加从未执行的源码目录。遵守仓库仅使用 main 的贡献约定，
不把私密原始论文作为证据提交。
